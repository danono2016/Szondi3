# Manualul Szondi — Poarta de finalizare a capitolelor

**Statut:** OBLIGATORIU  
**Regulă:** niciun capitol nu devine `FINAL` dacă lipsește o etapă relevantă.  
**Constituție de proiect:** `MANUAL_CREATION_MANIFEST.md`

## Fluxul obligatoriu

`întrebarea reală a cititorului -> cercetare 10/10 -> matrice de relevanță -> note conceptuale -> decizie deep corpus -> control formal/practic -> arhitectură proprie -> draft propriu -> verificare doctrinară/vizuală -> completitudine -> independență -> control epistemic -> stil -> experiența cititorului -> deep impact / continuity pass -> FINAL`

---

# GATE 0 — Întrebarea capitolului

Trebuie să existe înaintea cercetării:

- întrebarea centrală;
- competența cititorului la final;
- frontiera: ce nu introducem încă;
- relația cu capitolele vecine.

**FAIL** dacă titlul este doar o temă fără problemă cognitivă clară.

---

# GATE 1 — Cercetarea 10/10

Toate cele zece surse canonice sunt verificate și clasificate explicit:

`CENTRALĂ / CONTRIBUTIVĂ / CONTROL / FĂRĂ CONTRIBUȚIE IDENTIFICATĂ`

Pentru fiecare sursă trebuie să fie clar:

- ce material relevant a fost găsit;
- dacă este doctrină primară, tradiție ulterioară sau doar control;
- ce formulări/figuri/tabele necesită revenire la PDF.

**FAIL** dacă o sursă este ignorată pentru că „probabil nu are nimic relevant”.

---

# GATE 2 — Matricea doctrinară

Se separă în notele de cercetare:

- afirmații testologice;
- reguli formale/calcul;
- definiții doctrinare;
- dezvoltări istorice ale doctrinei;
- contribuții Deri/Mélon;
- exemple/cazuri;
- inferențe clinice;
- incertitudini și conflicte.

**FAIL** dacă o afirmație dintr-un caz este ridicată la regulă fără suport general.

---

# GATE 2B — Decizia de deep corpus pass

După cercetarea locală 10/10 trebuie decis explicit dacă tema cere exploatare transversală suplimentară.

Deep corpus pass este **obligatoriu** când există una sau mai multe dintre situațiile următoare:

- conceptul traversează mai multe etape ale operei;
- apare în mai multe registre: genetic, pulsional, testologic, al Eului, clinic sau terapeutic;
- există formulări cronologic diferite;
- există multe compuse/forme lexicale;
- apar excepții sau calificări în cazuri secundare;
- un sens timpuriu este reinterpretat într-o lucrare ulterioară;
- riscul de modernizare tacită este mare;
- conceptul este structural pentru mai multe părți ale cărții.

Deep pass-ul urmărește **familii conceptuale**, nu doar cuvântul exact, și clasifică descoperirile în:

`RELATION / QUALIFIER-EXCEPTION / CHRONOLOGY / TENSION-CONTRADICTION / CASE-ONLY / LATER TRADITION / EDITORIAL CONSEQUENCE`.

Nu este necesar ca deep pass-ul să fie închis înainte de primul draft, dacă proiectul decide deliberat să folosească draftul ca instrument de testare. Dar capitolul nu poate deveni `FINAL` cât timp există `DEEP PASS IMPACT PENDING`.

**FAIL** dacă o temă densă este declarată epuizată doar pentru că toate cele zece surse au fost „bifate”.

---

# GATE 3 — Controlul formal și vizual

Pentru:

- semne;
- formule;
- tabele;
- praguri;
- indici;
- intensități;
- ordine de coloane/rânduri;
- distribuții de stimuli;
- scheme/figuri;
- cazuri-limită dependente de notație,

PDF-ul canonic este arbitrul vizual.

DOCX/OCR poate localiza textul, dar nu decide forma finală a unui tabel sau semn dacă există ambiguitate vizuală.

**FAIL** dacă o regulă formală este reconstruită din OCR incert sau din software fără control în sursă.

---

# GATE 4 — Arhitectura proprie a capitolului

Înainte de proză se construiește schema capitolului fără a urma ordinea sursei.

Trebuie să existe:

- intrarea în problemă;
- progresia conceptuală;
- locul exemplelor;
- locul anti-inferențelor;
- ieșirea către capitolul următor.

**FAIL** dacă schema este practic cuprinsul sursei tradus.

---

# GATE 5 — Draftul propriu

Primul text complet este `DRAFT`.

Draftul trebuie să fie inteligibil fără ca cititorul să aibă sursa deschisă lângă el și trebuie să aibă voce proprie.

Draftul este un **obiect de testat și atacat**, nu o versiune care trebuie protejată.

**FAIL** dacă este:

- traducere mascată;
- parafrază liniară;
- enciclopedie de definiții;
- listă de reguli fără mișcare intelectuală;
- text de tip help/documentație software.

---

# GATE 6 — Reverificarea doctrinară

După ce textul este scris independent, fiecare afirmație importantă este reverificată:

- există în sursă?
- este formulată la nivelul corect de certitudine?
- aparține lui Szondi sau unui autor ulterior?
- este explicația noastră prezentată ca explicație, nu ca doctrină?
- există contradicții între ediții sau perioade?

**FAIL** dacă manualul armonizează tacit surse care nu spun același lucru.

---

# GATE 7 — Controlul completitudinii

Capitolul trebuie să răspundă întrebării sale centrale fără goluri majore și fără a împinge în notă de subsol tocmai distincția esențială.

Se verifică:

- conceptele indispensabile;
- excepțiile/cazurile-limită relevante;
- terminologia germană unde traducerea singură pierde sens;
- anti-inferențele;
- relația cu restul arhitecturii.

**FAIL** dacă cititorul va avea nevoie de o regulă nepredată pentru a înțelege capitolul următor.

---

# GATE 8 — Controlul independenței

Se compară draftul cu sursele principale pentru a detecta:

- ordine prea apropiată;
- fraze recognoscibile;
- exemple distinctive reciclate;
- metafore/listări memorabile preluate;
- subtitluri/copiere de arhitectură.

**FAIL** dacă textul este doctrinar corect dar dependent expresiv de sursă.

---

# GATE 9 — Controlul clinic și epistemic

Fiecare trecere trebuie să fie legitimă:

`observație -> calcul -> doctrină -> ipoteză -> clinică`

Se verifică explicit:

- unde se termină faptul;
- unde începe interpretarea;
- unde există doar o posibilitate;
- unde lipsesc date;
- unde trebuie spus „nu știm încă”.

Nu se transformă:

- posibilitatea în fapt;
- cazul în lege;
- calculul în diagnostic;
- teoria istorică în psihologie contemporană;
- contradicția în certitudine armonizată.

**FAIL** dacă certitudinea crește doar prin acumularea de vocabular.

---

# GATE 10 — Controlul stilistic

Textul trebuie să fie:

- dens fără sufocare;
- conceptual fără rigiditate;
- clinic fără jargon administrativ;
- direct fără simplificare;
- viu fără ornament gratuit.

Se elimină:

- repetiția mecanică;
- paragrafele de umplutură;
- formulele AI generice;
- tranzițiile artificiale;
- enumerările excesive acolo unde proza ar gândi mai bine.

**FAIL** dacă sună ca wiki, raport, procedură de compliance sau help de aplicație.

---

# GATE 11 — Experiența cititorului

Se aplică `READER_EXPERIENCE_STANDARD.md`.

Întrebarea finală:

> **Poate fi citit ca o carte tipărită și produce plăcerea de a înțelege?**

Trebuie să existe:

- orientare;
- progres;
- tensiune intelectuală;
- exemple suficient de concrete;
- respirație;
- un final de capitol care schimbă efectiv ce poate vedea cititorul.

**FAIL** dacă textul este corect dar inert.

---

# GATE 11B — Deep impact review și continuity pass

Înainte de `FINAL`, orice deep corpus pass relevant trebuie să aibă impactul evaluat asupra manuscrisului.

Fiecare descoperire cu potențial impact primește una dintre deciziile:

`NO CHANGE / ADD / QUALIFY / MOVE / REMOVE / HOLD`.

Regula este:

> **mai întâi epuizăm familia conceptuală; apoi rescriem.**

După ce un cluster sau o parte există în draft și/sau a primit revizii din deep pass, se execută un `CONTINUITY PASS` pentru:

- repetiție;
- progresie;
- anticipări premature;
- goluri;
- tranziții;
- ritm;
- unitatea vocii;
- distribuția corectă a conceptelor între capitole.

**FAIL** dacă un capitol local bun strică progresia părții sau dacă deep pass-ul este încă `IMPACT PENDING`.

---

# GATE 12 — Declarația de stare

Un capitol poate deveni `FINAL` numai dacă:

- toate gate-urile relevante sunt PASS;
- toate incertitudinile rămase sunt explicit documentate și nu afectează afirmațiile centrale;
- nu există conflict sursă nerezolvat ascuns;
- tabelele/figurile/formulele au fost controlate vizual unde era necesar;
- capitolul respectă arhitectura globală;
- orice deep pass cerut de densitatea doctrinei este închis sau nu mai are impact nerezolvat;
- clusterul/partea a trecut continuity pass unde este necesar.

Dacă există dubiu: **rămâne DRAFT.**
